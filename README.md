# Minerva

Minerva is a self-hosted EPUB library server that publishes books through
[OPDS](https://opds-spec.org/) for Readest and other compatible reading apps.
It is designed for deployment on Render, with PostgreSQL for catalog metadata,
Catbox for EPUB files and Cloudinary for cover images.

## Features

- OPDS 2.0 catalog
- OPDS 1.2 compatibility catalog
- Public and private/hidden books
- Basic Auth and bearer API-token access
- EPUB upload and metadata extraction
- EPUB storage on Catbox (up to 100 MB per book) with protected downloads
- One-command backup of the whole library to a local folder
- Admin token creation, listing, and revocation
- Catalog search by title, description, subtitle, or author
- Reading progress and bookmark synchronization
- Readest-compatible KOReader Sync/KOSync progress API
- OPDS collections exposed as navigable sub-catalogues
- One-click Render deployment (`render.yaml`) with a health endpoint
- Kavita-inspired library browsing and administration UI
- Built-in web reader: table of contents, progress bar, themes, font and
  spacing controls, paged or scrolling layout, keyboard/tap/swipe navigation.
  Settings are remembered per browser; the reading position is shared with
  Readest through the sync account
- Covers extracted from uploaded EPUBs
- Lockout after repeated failed sign-ins

## Architecture

```text
Readest / OPDS client
          |
          v
       Render
   Next.js route handlers
      /       \
     v         v
PostgreSQL  Catbox + Cloudinary
 metadata   EPUBs    covers
```

PostgreSQL and Cloudinary are separate managed services; Render hosts the
application only. The database layer uses Drizzle ORM and is intentionally
provider-agnostic.

## Requirements

- Node.js 20+
- npm
- Managed PostgreSQL database
- Cloudinary account (cover images)
- Render account for hosted deployment

## Local setup

```bash
git clone <repository-url>
cd Minerva
npm install
cp .env.example .env.local
```

Minerva's Next.js app loads `.env.local` automatically. The Drizzle CLI is
configured separately to load `.env` first and `.env.local` second, with
`.env.local` taking precedence, so `npm run db:migrate` and
`npm run db:generate` can use the same local configuration.

Generate an admin password hash (Minerva uses `scrypt$...`, not Argon2):

```bash
npm run auth:hash-password -- 'replace-with-a-strong-password'
```

Put the complete single-line output in `ADMIN_PASSWORD_HASH`, escaping each
`$` as `\$` because Next.js expands unescaped dollar references:

```dotenv
ADMIN_PASSWORD_HASH=scrypt\$<salt>\$<derived-key>
```

Do not copy only the `scrypt$` prefix. The value must include the complete salt
and derived key from the command output.

If admin operations return `Authentication required`, inspect the loaded value
without printing it:

```bash
node --input-type=module -e "import nextEnv from '@next/env'; const {loadEnvConfig}=nextEnv; loadEnvConfig(process.cwd()); const value=process.env.ADMIN_PASSWORD_HASH || ''; console.log({length:value.length,format:value.startsWith('scrypt$') ? 'scrypt' : 'invalid'});"
```

An unescaped hash can be expanded by Next.js into an invalid value. After
fixing `.env.local`, restart the dev server.

To diagnose admin login without printing the hash:

```bash
npm run auth:check -- 'your-password'
```

Verify both external services without creating or changing any data:

```bash
npm run integration:check
```

This runs `SELECT 1` against PostgreSQL and Cloudinary's API ping. It loads
`.env`, then `.env.local` with `.env.local` taking precedence.

After changing `.env.local`, restart `npm run dev` or redeploy on Render. The
running server does not reload environment variables for an already-started
process.

Run the database migration and development server:

```bash
npm run db:migrate
npm run dev
```

The application is available at [http://localhost:3000](http://localhost:3000).

## Environment variables

| Variable | Purpose |
| --- | --- |
| `DATABASE_URL` | PostgreSQL connection string |
| `ADMIN_USERNAME` | Username for admin Basic Auth |
| `ADMIN_PASSWORD_HASH` | Password hash generated by `auth:hash-password` |
| `CATBOX_USERHASH` | Optional Catbox account userhash; lets deleted books be removed from Catbox |
| `CLOUDINARY_CLOUD_NAME` | Cloudinary cloud name |
| `CLOUDINARY_API_KEY` | Cloudinary API key |
| `CLOUDINARY_API_SECRET` | Cloudinary API secret |

Never commit `.env.local`, Cloudinary secrets, password hashes, or API tokens.

## Endpoints

### Public catalog

```text
GET /api/opds/2.0/catalog
GET /api/opds/1.2/catalog
```

Search the public catalog with `?q=search-term`.

### Private catalog

```text
GET /api/opds/private/2.0/catalog
GET /api/opds/private/1.2/catalog
```

Private catalogs require either:

```http
Authorization: Basic base64(username:password)
```

or:

```http
Authorization: Bearer <api-token>
```

For the private catalogue, Basic Auth uses `ADMIN_USERNAME` and the plaintext
admin password corresponding to `ADMIN_PASSWORD_HASH`. Bearer Auth uses an API
token created through `/api/admin/tokens`; it is not the admin password.

### Catalogue sub-folders

Collections act as OPDS sub-folders. Create one as an admin:

```bash
curl -u "$ADMIN_USERNAME:$ADMIN_PASSWORD" \
  -H 'content-type: application/json' \
  -d '{"name":"Science Fiction","slug":"science-fiction","description":"Sci-fi books"}' \
  https://books.example.com/api/admin/collections
```

Assign a book using the returned collection ID:

```bash
curl -u "$ADMIN_USERNAME:$ADMIN_PASSWORD" \
  -H 'content-type: application/json' \
  -d '{"bookId":"BOOK_UUID"}' \
  https://books.example.com/api/admin/collections/COLLECTION_UUID/books
```

The collection then appears as a navigable sub-catalogue in the OPDS 2.0
public/private feeds. A book can belong to multiple collections.

Private books are excluded from public catalogs and require authentication for
downloads.

### Admin and book operations

| Method | Endpoint | Purpose |
| --- | --- | --- |
| `POST` | `/api/admin/books` | Upload an EPUB |
| `GET` | `/api/admin/tokens` | List API tokens |
| `POST` | `/api/admin/tokens` | Create an API token |
| `DELETE` | `/api/admin/tokens/:id` | Revoke an API token |
| `GET` | `/api/books/:id/download` | Download a book |
| `GET` | `/api/progress/:bookId` | Read progress |
| `PUT` | `/api/progress/:bookId` | Save progress and bookmarks |

### Readest progress sync

Minerva also exposes the KOReader Sync protocol at the application root, which
allows Readest to sync reading progress without using KOReader as a reader:

```text
GET  /healthcheck
POST /users/create
GET  /users/auth
PUT  /syncs/progress
GET  /syncs/progress/:document
```

Sync clients cannot register accounts: `POST /users/create` requires admin
Basic Auth. Create the account under **Reading sync** on the `/admin` page,
then in Readest open **Settings → Integrations → Reading Sync → KOReader**, set
the server URL to the Minerva deployment URL, and sign in with that username
and password. The server stores progress per account and document hash.

The built-in web reader uses the same account: open **Reading settings** in the
reader and sign in under **Sync**. It then opens a book where the most recently
used device stopped, and reports its own position back.
This protocol syncs reading position only; Readest Cloud is still required for
Readest-native book, bookmark, highlight, and note synchronization.

The browser upload page is available at `/admin`. It sends admin Basic Auth
over HTTPS to the upload endpoint.

The home page (`/`) provides a public-only library view with search, book cards,
and download links. Private books are not returned by that page or its public
OPDS feed; they require the private OPDS URL and authentication. The admin page
provides upload, metadata editing, visibility changes, deletion, and library
statistics.

Create a client token with:

```bash
curl -u "$ADMIN_USERNAME:$ADMIN_PASSWORD" \
  -H 'content-type: application/json' \
  -d '{"name":"Readest"}' \
  https://books.example.com/api/admin/tokens
```

The token is returned only when it is created. Store it securely.

## Backing up the library

Copy every book to a folder on your computer; run it again any time and it only
fetches what is new:

```bash
npm run library:sync -- ~/Books/minerva --url https://books.example.com
```

It signs in as `ADMIN_USERNAME` and asks for the admin password (or reads
`MINERVA_ADMIN_PASSWORD`). Files are named `Title - Author [id].epub`. Books
deleted from the library are kept in the folder.

## Deployment

Minerva deploys to [Render](https://render.com) from `render.yaml`:

1. Create a managed PostgreSQL database, such as Neon or Supabase.
2. Create a Cloudinary account and collect its cloud name, API key, and API secret.
3. Push this repository to GitHub or GitLab.
4. In Render, choose **New > Blueprint** and select the repository.
5. Fill in the values Render asks for; they match `.env.example`. Keep the `\$`
   escaping in `ADMIN_PASSWORD_HASH`, because Next.js expands unescaped `$`
   even in real environment variables. `CATBOX_USERHASH` may be left empty.
6. Deploy. Each build runs `npm run db:migrate` before `npm run build`, so new
   migrations are applied automatically.
7. Add a custom domain in the service settings if desired.
8. Use the deployment URL in Readest. Catalog links are generated from the
   request host, so no app URL setting is needed.

The Blueprint uses Render's free plan in the Singapore region; change `plan`
and `region` in `render.yaml` to suit. A free service sleeps after about 15
minutes without traffic and takes up to a minute to wake. To keep it awake,
have an uptime monitor (UptimeRobot, cron-job.org, or similar) request
`GET /api/health` every 10 minutes. The endpoint returns `{"status":"ok"}`
and does not touch the database, so it will not keep a scale-to-zero
database running.

OPDS clients should use the deployed HTTPS endpoint. Do not expose the admin
page or private catalog over an unsecured connection.

## Project structure

```text
src/
  app/
    admin/                    Admin upload page
    api/admin/                Upload and token administration
    api/books/                Protected book downloads
    api/health/               Liveness check for Render and uptime pingers
    api/opds/                 Public and private OPDS feeds
    api/progress/             Reading progress and bookmark sync
  db/
    client.ts                 Drizzle/PostgreSQL connection
    schema.ts                 Catalog, token, and progress schema
  lib/
    auth.ts                   Authentication and password/token helpers
    catalog.ts                Catalog queries and visibility filtering
    book-storage.ts           EPUB files on Catbox
    cloudinary.ts             Cover images
    epub.ts                   EPUB validation and metadata extraction
    opds.ts                   OPDS publication mapping
```

## Current limitations

- Covers are extracted when a book is uploaded; books uploaded before that
  need a cover added through the admin editor.
- Uploads pass through the application server, which buffers the whole file;
  the free Render plan's 512 MB of memory is the practical ceiling.
- EPUBs are stored on Catbox (200 MB per file), which has no access control
  and no uptime guarantee. Minerva never shows the Catbox link and streams
  downloads itself, so book visibility still applies, but keep your own copies.
- There is no live PostgreSQL/Cloudinary integration test suite.
- OPDS interoperability has not yet been tested against every target client.
- Readest can connect to the public or private OPDS catalog. Readest's own
  progress, annotation, and book-file sync uses Readest Cloud or its documented
  integrations; it does not automatically call Minerva's custom progress API.
- Failed sign-ins are limited to 20 per client address per 15 minutes (admin,
  API token and sync logins); a locked-out client gets `401` until the window
  passes. Audit logging, backups, and monitoring still need production hardening.
- Review dependency updates before production deployment; run `npm audit`.
